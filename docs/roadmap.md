# 实施计划

本页只记录后续工作与验收目标；功能基线见 [实现状态](implementation-status.md)。计划中的命令、协议与数据模型需要实现及测试后再加入 [CLI 参考](cli-contract.md)。

## 本地读取与接口收敛

- 按命令收敛参数，拒绝不适用选项，避免无效参数被静默忽略。
- 补齐可取消、有截止时间的扫描，并统一多知识包故障隔离语义。
- 明确卡片过大、目录规模超限、无效时间及可选元数据的检查规则。
- 加强配置锁异常恢复、缓存损坏恢复及 Windows 路径边界测试。

验收要求：正常分页、部分覆盖和错误状态保持可区分；资源预算能限制真实处理成本；同一知识包在各平台返回一致的路径 ID、内容字节和 JSON 语义。

## Git 与持久化索引

- 增加仓库地址、包根和 ref 绑定，将 ref 解析为 commit 后读取 tree/blob。
- 不 checkout，不执行知识包仓库的 hooks，不自动初始化 submodule 或 LFS。
- 设计显式同步、增量变更、事务发布的 generation 和离线正文缓存。
- 隔离知识包绑定配置与授权上下文，提供可重建索引和缓存清理。

验收要求：分支前进不改变已固定提交的分页结果；同步中断保留旧版本；并发刷新不会发布混合索引；不完整枚举不能误删条目；离线命中、缺失与权限失败分别报告。Git 降级和实际传输成本必须可见。

## 对象存储与远端知识包

- 优先接入 S3 兼容对象存储，按实际需求评估其他 provider。
- 评估清单导航与无清单分页列举，显式声明可列举、条件读取和版本固定能力。
- 设计版本化远端读取协议或专用适配器，统一凭据引用、代理、超时、重试与下载预算。
- 对导入的远端绑定设计显式激活流程，限制重定向时的凭据转发。

清单和远端协议属于工具扩展，不改变普通 OKF 文件的要求。ETag 不直接等同内容哈希；无法保证跨文件一致性时应使用观测视图。

验收要求：同一 fixture 经各知识包读取后模型与原文字节一致。使用实际 Git、S3 测试服务与 HTTP fixture 验证分页、更新、删除、403、限流、超时和重定向，不以 mock 替代集成验收。

## 检索、关系与 Agent 消费

- 加入明确覆盖范围的全文索引，评估中文 ngram、代码符号和中英混合查询。
- 增加章节选择、链接关系与断链诊断，固定原始引用定位。
- 让任务上下文按预算选择正文，并提供选择依据、覆盖缺口与继续入口。
- 评估相关性排序、多知识包结果融合及机器可读帮助。

验收要求：统计定位成功率、原文引用正确率、披露字节与调用次数；Agent 能识别缺失、过期和部分覆盖。关系解析应覆盖引用式链接、片段和代码围栏，不凭文本相似度推断业务关系。

## 发布与性能

发布件应包含版本信息、可执行文件、校验和与一致的消费 Skill。验收使用全新安装的二进制、真实知识包和各平台测试结果。

性能评估使用固定的概念数量、文件大小分布、硬件与缓存冷热状态，同时记录读取字节、目录列举和文件读取次数。先建立基线，再决定全文索引、内容寻址缓存或后台处理的引入方式；不以未经测量的延迟目标替代结果。
