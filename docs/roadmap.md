# 实施计划

项目定位为面向 Agent 的只读知识消费 CLI。已实现能力见 [实现状态](implementation-status.md)，命令契约见 [CLI 参考](cli-contract.md)。

## 1. 持续交付验证

PR #10 已合并且三平台 CI 通过。本轮已固定发行平台标签和 Rust 版本，增加运行库检查及三平台指定基线升级/回退步骤，见 [发行基线](releases.md#固定发行基线)。下一步在远端验证新矩阵、补齐最低系统实际运行证据，再完成 tag 和 Release 草稿验收。

## 2. 检索规模与任务质量

目录范围筛选、12 个 CLI 消费任务回放及独立持久候选索引原型已实现。下一步根据真实任务扩充语料，固定模型与提示后测量自然语言答案质量；目前回放只验证证据和覆盖条件。

有限预算评测已量化按路径前缀扫描的召回损失。候选原型分别计量倒排读取与正文检查，并保留短词回退；下一步补齐生产卡片派生、数据库兼容、完整性检查和同步修复后，再评估接入。不同来源继续保留独立引用，不能将相同正文预算解释为相同总工作量。

验收：相同任务与预算下比较优化前后结果，保持文件、哈希、字节范围和 generation 可追溯；不能把确定性检索命中等同于 Agent 答案正确。

## 3. Git 远端深化

当前公开 HTTPS 获取已具备可控故障测试、独立诊断、对象占用预算和保留历史的压缩。后续按使用需求设计私有凭据引用、精确传输限制及历史对象过期策略。

验收：不泄露凭据，失败保留绑定，清理不影响仍使用的提交。现有对象预算采用采样检查，不作精确网络字节承诺；当前压缩保留历史，不承担版本回收。

## 4. 格式与导航兼容

只读上游差异报告与手动工作流已实现，见 [上游兼容检查](upstream-compatibility.md)。新规范或语料有变化时，按差异分类补充回归，再显式更新固定版本。

根据真实语料扩展显式锚点规则与附件类型，评估图片和自定义 HTML 导航需求。关系查询只表达文档声明的直接链接与来源，保持预算、断链和覆盖语义一致。

## 按需求评估的存储扩展

S3 等新存储适配器待明确使用场景后排期，继续复用 CLI 应用端口。版本条件、分页、重试与下载预算需先定义；不增加普通 OKF 文件的格式要求。
