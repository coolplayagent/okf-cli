# 实施计划

本页只记录尚未完成的工作，按建议实施顺序排列。已交付功能与限制见 [实现状态](implementation-status.md)，现有接口见 [CLI 参考](cli-contract.md)。

## 1. 链接检查扩展

明确 Markdown 片段锚点的生成约定，再增加锚点与普通附件检查。继续区分结构错误、质量警告和操作故障，分别报告检查覆盖。

验收：覆盖中文标题、重复标题、附件缺失和路径越界；缺少可选字段、未知类型和扩展字段保持现有消费行为。

## 2. Git 远端运维

在现有公开 HTTPS 获取与固定提交读取的基础上，设计私有仓库凭据引用、授权隔离、对象缓存清理与传输量限制。使用可控 HTTPS 测试服务补齐鉴权失败与传输中断场景。

验收：凭据不进入绑定或诊断输出；获取失败保留旧绑定；清理不删除仍被绑定引用的对象；离线缺失、授权失败与超限具有可区分的诊断。

## 3. 检索规模与质量

以 [性能基线](performance.md) 为起点，扩展语料规模及中文、代码符号、中英混合查询集，测量同步成本、查询内存、延迟与召回质量，再决定是否引入倒排索引、分词或减少同步读取。

验收：优化前后使用同一任务集对比；同步中断与并发发布仍保留一致版本，不完整列举不误删条目，结果片段可还原至对应原文字节。

## 4. Agent 上下文评测

建立真实任务集，统计定位成功率、引用正确率、披露字节与调用次数。根据结果改进章节选择，评估多知识包融合与机器可读帮助的必要性。

验收：Agent 能识别过期内容、缺失索引和部分覆盖；继续读取保持 generation 一致，引用可追溯至文件、哈希和字节范围。

## 5. 跨平台发布验收

运行现有三平台构建与打包工作流，收集实际 CI 结果，并在全新环境验证安装、运行依赖与消费 Skill 一致性。当前工作流仅上传构建产物，正式发布渠道与版本策略仍需确定。

验收：Windows、Linux、macOS 分别完成优化构建、测试及无编译工具环境下的冒烟检查；发行包与清单校验和一致。本地 Windows 结果不能替代其他平台验证。

## 按需求启动的扩展

S3、只读 MCP 和关系导航尚未实现，待明确使用需求后确定优先级。接入对象存储时需定义分页列举、条件读取、版本固定、代理、重试与下载预算；清单和读取协议作为工具扩展，不增加普通 OKF 文件的格式要求。

验收：使用实际测试服务覆盖更新、删除、权限拒绝、限流、超时和重定向；不同适配器读取同一内容时保持模型与原文字节一致。ETag 不直接等同内容哈希，无法保证跨文件一致性时使用观测视图。
