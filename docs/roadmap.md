# 实施计划

项目定位为面向 Agent 的只读知识消费 CLI。已实现能力见 [实现状态](implementation-status.md)，命令契约见 [CLI 参考](cli-contract.md)。

## 1. 持续交付验证

PR #7 的三平台验收已通过。当前已准备按 Rust target 命名的校验包、构建来源、tag 一致性检查和手动创建 GitHub Release 草稿的流程。下一步验证新工作流，确认支持平台及系统依赖，再选择正式版本并发布；安装与升级步骤见 [发行说明](releases.md)。

## 2. 检索规模与任务质量

当前已提供审核层级、有效期与固定评估时间筛选，以及跨包同名、重复、冲突、过期证据和缺失索引的逐包评测基线。下一步定义多包全文查询的全局结果、字节与扫描预算，再实现故障隔离和确定性合并。每个包保留独立 generation 与来源，当前 CLI 全文查询仍要求一个知识包。

继续补充用户实际任务与真实 Agent 执行记录；先测量 1千、5千、1万文档下的冷启动、RSS 和同步成本，再决定候选查询与原文读取分离、倒排索引等优化。需要知识质量门槛时使用已提供的 `validate --max-warnings`，默认格式检查行为保持兼容。

验收：相同任务与预算下比较优化前后结果，保持文件、哈希、字节范围和 generation 可追溯；不能把确定性检索命中等同于 Agent 答案正确。

## 3. Git 远端深化

当前公开 HTTPS 获取已具备可控故障测试、独立诊断、对象占用预算和保留历史的压缩。后续按使用需求设计私有凭据引用、精确传输限制及历史对象过期策略。

验收：不泄露凭据，失败保留绑定，清理不影响仍使用的提交。现有对象预算采用采样检查，不作精确网络字节承诺；当前压缩保留历史，不承担版本回收。

## 4. 格式与导航兼容

根据真实语料扩展显式锚点规则与附件类型，评估图片和自定义 HTML 导航需求。关系查询只表达文档声明的直接链接与来源，保持预算、断链和覆盖语义一致。

## 按需求评估的存储扩展

S3 等新存储适配器待明确使用场景后排期，继续复用 CLI 应用端口。版本条件、分页、重试与下载预算需先定义；不增加普通 OKF 文件的格式要求。
