# 实施计划

项目定位为面向 Agent 的只读知识消费 CLI。已实现能力见 [实现状态](implementation-status.md)，命令契约见 [CLI 参考](cli-contract.md)。

## 1. 持续交付验证

`v0.1.0` 已完成三平台发行验收并发布，固定发行矩阵、运行库检查与升级/回退流程已实测，见 [发行说明](releases.md)。当前 Skill 更名为 `okf-cli` 的改动已完成 Windows GNU 本地全量验证，尚未发布；下一步完成该改动的三平台 CI，并按新版本执行 tag 与发行验收。最低操作系统的实际运行证据仍需补齐。

## 2. 检索规模与任务质量

目录范围筛选、12 个 CLI 消费任务回放、候选原型和显式启用的生产候选检索已实现。六个自然语言任务、隔离语料准备与评分方法见 [Agent 消费评测协议](agent-evaluation.md)。下一步确定模型版本及费用预算，由执行宿主实施调用与披露限制，再运行重复对照与答案评分；目前未测量模型答案质量。

生产候选检索已复用卡片派生并覆盖事务发布、旧库读取、完整性检查、同步修复和容量回退。默认路径扫描继续作为基线。下一步用真实大包评估倒排交集顺序、多包配额和索引体积，依据收益与退化决定是否改变默认策略；不能将相同正文预算解释为相同总工作量。

验收：相同任务与预算下比较优化前后结果，保持文件、哈希、字节范围和 generation 可追溯；不能把确定性检索命中等同于 Agent 答案正确。

## 3. Git 远端深化

已实现私有凭据引用（`env:VAR` / `file:PATH`）、精确传输限制（`--max-fetch-bytes`，对象字节差集核算）与显式历史对象回收（`bundle cache --gc`）。凭据只注入子进程环境，不落盘、不进响应；失败保留旧绑定，清理不影响仍使用的提交。

验收：不泄露凭据，失败保留绑定，清理不影响仍使用的提交。现有对象预算采用采样检查，不作精确网络字节承诺；`--max-fetch-bytes` 提供精确对象字节承诺（不含 wire 层开销）。

## 4. 格式与导航兼容

只读上游差异报告与手动工作流已实现，见 [上游兼容检查](upstream-compatibility.md)。新规范或语料有变化时，按差异分类补充回归，再显式更新固定版本。

已实现图片引用检查（`--attachments` 下 `images_included`/`images_checked`）与 `id`/`name` 形式显式 HTML 锚点匹配（`--anchor-style headings-v1`）。下一步根据真实语料扩展其他附件类型与锚点规则，评估图片和自定义 HTML 导航需求。关系查询只表达文档声明的直接链接与来源，保持预算、断链和覆盖语义一致。

## 按需求评估的存储扩展

S3 等新存储适配器待明确使用场景后排期，继续复用 CLI 应用端口。版本条件、分页、重试与下载预算需先定义；不增加普通 OKF 文件的格式要求。
