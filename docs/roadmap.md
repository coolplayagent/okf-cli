# 实施计划

项目定位为面向 Agent 的只读知识消费 CLI。已实现能力见 [实现状态](implementation-status.md)，命令契约见 [CLI 参考](cli-contract.md)。

## 1. 持续交付验证

PR #9 已合并且三平台 CI 通过，已合并主线的三平台打包工作流及指定 Windows 二进制对的升级/回退验收也已完成，见 [发行实测](releases.md#三平台打包实测)。下一步固定构建环境与最低系统版本，完成 tag 和 Release 草稿工作流验收，再准备正式版本。本轮新增命令尚需后续远端 CI 验证。

## 2. 检索规模与任务质量

在已实现的多包查询与 [跨包评测](retrieval-evaluation.md#跨知识包对比) 基础上，补充实际用户任务和固定 Agent 执行协议，评估排序、扫描份额分配与重复证据展示。

有限预算评测现覆盖不均衡知识包、路径末尾、筛选稀疏命中与重复来源，已量化按路径前缀扫描的召回损失，见 [预算评测](retrieval-evaluation.md#有限预算与不均衡知识包)。结合千至万文档的成本基线，下一步比较索引候选筛选和现有策略；任何优化须保持预算语义，并报告收益与退化。不同来源仍需保留独立引用。

验收：相同任务与预算下比较优化前后结果，保持文件、哈希、字节范围和 generation 可追溯；不能把确定性检索命中等同于 Agent 答案正确。

## 3. Git 远端深化

当前公开 HTTPS 获取已具备可控故障测试、独立诊断、对象占用预算和保留历史的压缩。后续按使用需求设计私有凭据引用、精确传输限制及历史对象过期策略。

验收：不泄露凭据，失败保留绑定，清理不影响仍使用的提交。现有对象预算采用采样检查，不作精确网络字节承诺；当前压缩保留历史，不承担版本回收。

## 4. 格式与导航兼容

根据真实语料扩展显式锚点规则与附件类型，评估图片和自定义 HTML 导航需求。关系查询只表达文档声明的直接链接与来源，保持预算、断链和覆盖语义一致。

## 按需求评估的存储扩展

S3 等新存储适配器待明确使用场景后排期，继续复用 CLI 应用端口。版本条件、分页、重试与下载预算需先定义；不增加普通 OKF 文件的格式要求。
